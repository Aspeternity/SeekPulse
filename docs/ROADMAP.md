### B 阶段强约束

- 用户明确要求第一次打开网页就自己注册用户名、密码和确认密码；**无默认账户、无初始化码、无日志查密钥、无强制向导**。此约束优先于曾被否决的助手 ADR 草案。
- B 阶段镜像标签 `web-first-b-NOT-PUBLISHED` 是故意无法拉取的占位符，离线 GitHub Runner 的真实 Docker smoke **不等于**用户 Portainer 可直接安装或正式 GHCR 已发布。
- A 阶段验收、B 阶段开发授权、B 人工验收、PR 合并、真实部署与 GHCR 发行必须分别批准；不操作用户真实 NAS/PVE。
- 旧 S7 父 Issue #16 的实机/稳定版闸门依然受独立授权约束；本产品化路线不自动解除旧 RC1 风险。

### 开发原则

- 顺序以数据和接口依赖为准；新需求须评估范围和必要性，避免功能膨胀。
- 每阶段至少一个可验收的 PR，PR 相关 Issue 建立依赖；不能把未完成和已验收混为一谈。
- 按 `AGENTS.md` 的流程核验“唯一写入负责人”和仓库现状。
- 提前完成一个阶段的设计文档不构成对该阶段的代码执行授权。
