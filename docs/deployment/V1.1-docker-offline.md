- 既有 `Dockerfile`、`docker-compose.yml`、`requirements.txt` 保留为原版 RSS Bot；不会静默将运行中的旧容器升级到 V1.1。

- 新增 `compose.v11.yaml`：**只引用外部镜像、不要求用户本地 build**，镜像由 `SEEKPULSE_IMAGE` 指定（建议审批发布后固定 `@sha256:` Digest）。适用于未来 Linux Docker Engine standalone + Compose：PVE 内运行 Docker/Portainer Stack、群晖 NAS Container Manager 的项目/Compose。**尚未经过实际 Portainer/群晖版本或 CPU 架构测试。** Swarm `docker stack deploy` 不是本版已测试目标。
- 不默认重启：`restart: "no"`，以免初始化前不断重试。用户独立验收 Gate D 以后，再决定是否允许自动重启。

## 2. 运行配置示例（仅未来获批后使用）

文件 `.env.v11.example` 只有假占位符，可复制到操作者自己的受保护路径，**不得将填入的 .env、Session、数据库或备份提交到 GitHub 或发送 AI**。在 Portainer Web Editor 配置 Stack 环境参数时，可以用相同名称的变量替代本地 `.env`；Portainer 管理员和 Docker 宿主管理员通常有权限读取容器环境变量，切勿共享其输出或 `docker inspect` 原文。

在本地主机由操作者创建**绝对路径**的专用数据目录，例如 PVE 上 Docker 宿主的 `/opt/docker/seekpulse/data`，或群晖支持的 `/volume1/docker/seekpulse/data`；填入 `SEEKPULSE_DATA_DIR`。容器内固定挂载到 `/app/data`，包括 `bot.db`、WAL/SHM、实例 lock 与将来单独授权提供的 `.session`。目录必须对非 root 的容器 UID/GID（默认 10001:10001，或明确设置的 `SEEKPULSE_UID` / `SEEKPULSE_GID`）可读写；现有目录无法写入时，应在**部署授权阶段**处理权限，而不是将容器改为 root。Compose 使用 `create_host_path: false` 阻止写错路径时默默创建目录。

必需变量：`SEEKPULSE_IMAGE`、`SEEKPULSE_DATA_DIR`、`BOT_TOKEN`、非空 `ALLOWED_USER_IDS`、`SEEKPULSE_ADMIN_TG_USER_ID`、`SEEKPULSE_WEB_PASSWORD_HASH`。现有交互式 `python -m app.web_auth` 可在**可信本地终端**输入密码（不少于 12 字符）生成 scrypt hash；不要在命令行参数或历史里写明文密码。环境中的 `SEEKPULSE_V11_ENABLE=1` 与 `--run` 由专用 Compose 明确写入，但**不会**绕过数据库尚未 Prime 的启动拒绝。TG 采集另需 `SEEKPULSE_TG_API_ID`、`SEEKPULSE_TG_API_HASH`、`SEEKPULSE_TG_SESSION` **三项同时存在**，且 Session 是被批准、已存在的实际 `.session` 文件，路径应在持久化目录中，不能交互登录或自动生成。RSS 不需要该 Session。

Bark/ntfy 的正式目标由管理员 Web 配置独立 target_id、`secret_ref`；Compose 中示例 `SEEKPULSE_PUSH_BARK_PRIMARY` / `SEEKPULSE_PUSH_NTFY_PRIMARY` 仅作受保护环境值载体，真实目标保持禁用直至通过授权与校验。绝不将设备 URL/Key 放入数据库或 Issue。额外的安全引用通过私有 Stack/Compose 环境新增同名 `SEEKPULSE_PUSH_<REF>` 变量，受官方 HTTPS 目的地限制；不是任意 URL Webhook。

## 3. 管理 Web 的网络设计

V1.1 Web 原有中间件要求**实际 TCP 客户端来自 127.0.0.1/::1，HTTP Host 也必须是 localhost/127.0.0.1/::1**，并拒绝 Forwarded/X-Forwarded。Docker bridge 下简单发布 `127.0.0.1:8765:8765` 仍可能让应用观察到非 loopback 的容器网桥源地址，从而返回 403。

因此此 Compose **仅面向 Linux standalone Engine，采用 `network_mode: host` 且不配置 `ports:`**。程序继续只监听宿主机回环 `127.0.0.1:${SEEKPULSE_WEB_PORT:-8765}`，不会自动向局域网或公网开放管理页面。未来经授权可由管理员在自己的电脑使用可信 SSH 本地转发（例如 `ssh -L 8765:127.0.0.1:8765 <user>@<docker-host>`），浏览器访问 `http://127.0.0.1:8765`。实际 SSH/端口可达性、网络占用与群晖兼容性**均未测试**。不要改成 `0.0.0.0`、映射公开端口或放松 S5 IP/Host/CSRF 校验来“修复”403；如未来需要可信 LAN Web，须独立 ADR/授权。

## 4. 为什么当前不能直接复制 Compose 运行

虽然 V1.1 运行、路由和目标代码已经在 `main=210dd64e19c2de4e17d088ce5e12349dccdd2797`，**仅完成离线开发**。Gate B 约定 `--prepare` 要求经 S6 校验的备份 bundle、旧实例停机和人工确认；`--run` 则必须已经迁移/Prime，不补发旧帖。**即使是新建空数据库，也不能绕过现有显式 Prime/备份检查**。此外现有部署旧镜像可能没有任何单实例锁，V1.1 不能与其同时向同一目标发信。

因此“拉取镜像 → 运行 Compose → 正常开始发送”仍需后续 Gate D 的**新实例首次初始化方案、旧数据迁移/回滚实操、镜像正式发布、真实 TG/Bark/ntfy 账户授权**及现场验收；本次只交付可审计的镜像/编排与离线测试，不执行以上操作。相关阻断必须如实记录，不能通过自动建库/删库/补发历史来掩盖。
