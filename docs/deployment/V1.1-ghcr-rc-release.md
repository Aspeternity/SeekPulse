## One-shot publisher

The separately approved release workflow is .github/workflows/v11-ghcr-rc-publish.yml.

- A pull request runs read-only source and all-app regression tests, never package push/sign/Tag/Release.
- Adding the workflow file to main triggers the approved, one-time on-push release. Later changes to other files do not retrigger. An already existing RC Git tag or GitHub Release aborts the run.
- Native AMD64 and ARM64 each build their actual version-labeled image once. The same locally scanned image ID is tagged and pushed, not rebuilt. Existing Trivy OS/PyPI/CycloneDX and complete package inventory, revised version label, source SHA and no-network nonroot smoke all fail closed if requirements do not match.
- The publisher reads both platform manifest digests from GHCR and builds a staging multi-arch index containing exactly these two distinct previously scanned platform manifest digests. It re-pulls the real staging index by immutable GHCR digest, runs fresh Trivy and CycloneDX for both pulled architectures and validates image identity, source labels, no baked secrets, OS/PyPI inventory and all-five-severity zero count. The real remote platform manifests must match the hashes published by the native jobs.
- The package must be anonymously pullable before promotion; if it is still private, no official RC Tag/Release is created. Package visibility may need changing via GitHub package settings without disclosing credentials.
- The exact remote index digest is signed and independently verified with keyless Sigstore Cosign and the expected main-branch GitHub workflow identity. GitHub-native OIDC signed provenance and both remote-pulled platform CycloneDX SBOM attestations must verify against the same digest and source commit.
- Only after all steps succeed does the workflow tag that exact index as v1.1.0-rc.1, create a Git tag at the same main commit and create the GitHub prerelease. No floating latest tag.
- On failure, already-pushed candidate platform/staging tags are real remote artifacts, but there must be no claim that official RC release succeeded. Do not report a remote digest until it is read back.
