# ADR-0002：原子去重和持久化投递；不承诺严格 Exactly Once

- 状态：已批准的设计基线，待 S2/S4 实施
- 日期：2026-10-13

## 背景

上游先检查已送达、发送后才写历史，双来源并发可能重复。多目标可能出现部分成功，不能使用整体的 `sent` 布尔值。

## 决定

统一 `(user_id, post_id, target_id)` 唯一任务键。通过 SQLite 事务创建和租约认领、离线恢复与有界重试，并保存每次发送结果。任一来源后到不会产生同目标第二任务；规则命中多目标允许并行。

## 边界

第三方 API 与 SQLite 不能联合原子提交。API 接受后、本地写入前崩溃可能导致极端重复。产品保证正常情况下去重、失败可追踪、重启可恢复，而非严格 Exactly Once。

## 约束

数据库写事务不可跨 HTTP 等待；平台限流必须遵守；暂停和规则修改作用于未开始任务，不能保证撤回已发起请求。
