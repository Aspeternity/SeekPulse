# SeekPulse Web-first · A 阶段交互原型 V3

> 原型只供 **页面布局、产品流程和交互验收**。不是已经交付的后端、Web 服务、真实管理员认证或 Docker 安装。
> 对应 Issue [#59](https://github.com/Aspeternity/SeekPulse/issues/59)、Draft PR [#60](https://github.com/Aspeternity/SeekPulse/pull/60)。本阶段 **不修改 main、app、Compose、数据库、真实账号与通知**。

## 打开与操作

1. 下载本目录的 `seekpulse-web-first.html`，使用 Edge / Chrome 打开。
2. 首次展示独立 **创建管理员** 页面。使用虚构用户名（至少 3 位）与虚构密码（至少 8 位）体验注册，随后进入独立登录页面。
3. 登录后可体验 **运行概览、监控来源、关键词规则、通知管理、推送历史、系统设置** 六大入口。
4. 点击「系统设置」再选择子分类：**常规偏好、账户与安全、数据与备份、运行与诊断、关于与更新**。桌面版使用左侧二级导航，手机版使用下拉分类选择器，每次只展示当前分类。
5. 可模拟更换界面主题/默认首页、密码修改弹窗、模拟备份状态及校验、日志级别、诊断摘要；没有真实后端。
6. 尝试 RSS 和 TG 分别启停、双源协同、Telegram Bot 可选的通知和命令、Bark/ntfy 独立使用、关键词新增/编辑及历史操作。

**不得填写任何真实密码、Bot Token、Telegram API Hash、手机号、Session、Bark Key、ntfy Token 或设备凭据。** 模拟操作只存在浏览器内存，刷新即重置；注册及登录页只是交互演示，没有真实密码验证或数据库存储。

## Web-first 正式架构约束

| 层次 | 确定职责 |
|---|---|
| Docker / Portainer | 镜像、宿主端口、持久化数据目录、运行保护 |
| Web 管理中心 | 独立首注与登录；来源、规则、通知、历史、设置和诊断的主入口 |
| 配置服务与运行管理器 | 验证和保存配置、管理组件启停、同步真实健康状态 |
| RSS / TG 引擎 | 分别启停，单 RSS / 单 TG / 双源协同 / 全暂停；双源共用统一帖子 ID、字段补全、持久去重与恢复 |
| 规则与通知 | Web/Bot 共用业务规则，Telegram Bot 启用后兼有命令管理，Bark、ntfy 不依赖 Bot |
| 持久化 | SQLite 数据及受保护敏感配置；恢复路径严格区分新装与已有数据库 |

## V3 本次 UI 整改

- 将原先「系统设置」四张并列拥挤卡片改为 **五个专属分类视图**，常规、账号、数据、诊断和版本不再混排。
- 设置面板统一采用「分类 → 页面标题/说明 → 单列分组 → 配置行 → 就地操作」模式；配置页保留必要的保存按钮和状态反馈。
- 手机端不塞两套侧栏，改为设置分类下拉选择；同时调整窄屏顶部导航/提示条，防止面包屑被挤成多行。
- 主导航图标统一为内联 SVG 线性图标，无外部依赖；概览提示条从亮蓝营销式横幅改为低干扰的状态提示。
- 系统设置只保留系统偏好与维护；**RSS 轮询和开关只在监控来源页面编辑**，避免重复入口和状态冲突。
- 保留先前 V2 的独立注册登录、无强制安装向导、Bot 可选、RSS/TG 四种合法模式。

## 验收与限制

- 共享 V3 设置页面的桌面、深色和 390px 窄屏模拟 HTML 已在 Chromium/Playwright 测试：五分类切换、保存偏好、模拟备份及校验、修改密码弹窗、导航布局；0 pageerror、0 外部请求。
- 注意该本地 UI smoke 使用的是原型 V1 壳 + 与 V3 相同的新增设置实现和样式，**不是完整 V3 HTML 的逐字节浏览器验收**；GitHub PR 最新 HEAD 的 CI 应单独核实，不能拿此前 V2 CI 代替。
- 所有模拟按钮不执行真实保存或修改，也不访问 NAS/PVE、Portainer、Telegram、Bark、ntfy。
- V3 仍待用户 UI 验收和必要修改。**阶段验收 ≠ PR 合并授权；B 阶段后端改造须另行批准。**

设计思路参考：Linear 对账户与应用设置分组的处理、GitHub Primer Settings 的分组导航。仅参考信息架构，不复制其页面源码或商标。
